# API 2.17：小智语音适配候选

状态：2026-11-05 本地实现与主机回归通过，四台设备验收进行中。不是冻结发行版。
候选主系统为 2.0.32，新老板各自构建；分区布局和 XAPP 格式 1 不变。
API 2.16 原有结构、符号、权限与音频内存管理保持兼容。

## API 2.17 启动顺序

声明最低 API 2.17 的 APP 自己调用 `x622_wifi_start()` 获取 Wi-Fi；宿主不再在
`xapp_init` 前抢先启动无线网络。这样 APP 能先创建大块编解码状态，再初始化网络。
最低 API 2.16 及以前的 APP 保持原先的自动 Wi-Fi 启动行为；BLE/ESP-NOW 的规则不变。
退出与 trap 仍由宿主统一停止服务，APP 无须自行处理系统级回收。

## 真实导入签名

WAMR 的 `*~` 表示指针与长度组合，非法线性内存地址由运行时拦截。

| 导入 | WAMR 签名 | 所需权限 | 最低 API |
|---|---|---|---|
| `ws_open_ex` | `(*~)i` | Wi-Fi + HTTP（96） | 2.17 |
| `ws_status_ex` | `(i*~)i` | 同上 | 2.17 |
| `http_request_headers` | `(*~*~)i` | 同上 | 2.17 |
| `http_release` | `()i` | Wi-Fi + HTTP | 2.17 |
| `opus_start` | `(*~)i` | 播放 + 录音（1536） | 2.17 |
| `opus_submit` | `(ii*~)i` | 同上 | 2.17 |
| `opus_read` | `(i*~)i` | 同上 | 2.17 |
| `opus_status` | `(i*~)i` | 同上 | 2.17 |
| `opus_stop` | `(i)i` | 同上 | 2.17 |

头文件：`sdk/xapp/x622_net_ex.h`、`x622_http_headers.h`、`x622_opus.h`。
设备加载器、Python 校验器、浏览器安装校验器同版本拒绝旧 API 应用导入新能力。

## WSS 和 HTTP 请求头

新 WS 配置 1288 字节，包含旧配置与 1040 字节的请求头块。旧 `ws_open` 仍按原 ABI
只接受 WS；新接口可选 WS/WSS。请求头最多 8 项、合计 1024 字节；名字最多 48 字节，
值最多 512 字节，name/value 均以 NUL 结束，禁止重复名字、控制字符和传输保留头。
允许 Protocol-Version、Device-Id、Client-Id、Authorization、Activation-Version、User-Agent。
凭据复制到宿主管理的有界内存，完成、取消或退出时清零。不会保留 WASM 指针。

WSS 使用系统 CA、原域名 SNI 与主机名检查；禁止跳过验签、自动降级和自动重定向。
握手分步在网络工作线程执行，不占用 APP 主回调。每个 APP 最多一个 WSS；开始 TLS
握手时不得有其他 IP 会话，避免同一网络工作线程被冷握手拖住。OPEN 后可按已有规则
使用相同已解析主机或数字 IP 的其他会话。旧版多 WS/UDP 行为不变。

状态 64 字节：保留原 48 字节网络状态，附加 DNS/连接/TLS/升级/数据阶段、TLS 错误、
证书标志和 HTTP 升级状态。队列是有界的；发送成功只表示本地入队，不是远端送达证明。
网络工作线程为 WSS 预留 8 KiB 栈；其他 TLS 动态内存需要在真机同时负载下测量。

`http_release()` 是显式、幂等的空闲释放：完成响应已经由 poll 复制到 APP 后，可归还
本 APP 的 HTTP 任务栈和请求/响应存储，再进入 WSS 或音频阶段。仍有请求在执行时返回
BUSY，不取消请求、不等待网络；释放后 poll 的 phase 为 0，下次请求按需重新创建任务。
旧 APP 不调用它时，行为和生命周期保持不变；它不释放 Wi-Fi、音频或其他 APP 的资源。

## Opus 所有权

配置 32 字节。单 owner、编码/解码二选一，每次 start 返回新 generation 句柄。
编码：16 kHz PCM16LE 单声道，20/40/60 ms，6–32 kbit/s，复杂度 0。
解码：选择 16/24 kHz 输出，20/40/60 ms 单声道。非法、变帧长或不匹配帧明确返回错误。
每包上限 1275 字节，PCM 上限 2880 字节。

队列总计两项（排队 + 正在处理 + 尚未读取的结果），满时返回 BUSY，不静默覆盖。
submit 同步复制输入；read 返回 32 字节元数据加实际 payload，返回 0 表示尚无结果。
read 缓冲必须提供 2912 字节，status 为 64 字节。坏包作为带错误的结果返回，不使后续帧永久失效。
stop 为异步取消，直到 worker 完成才回收；退出/trap 的统一清理会等待持有者释放。

Opus 不申请音频租约，也不自动开关麦克风或扬声器。APP 用已有 PCM 服务做输入输出。
新工作区仅在 start 后存在，当前实验编码栈 32 KiB、解码栈 20 KiB，状态和两项队列约 7 KiB。
库的全编码器建议为 40 KiB；32 KiB 仅针对本接口固定的单声道/16 kHz/复杂度 0。
旧板独立测量 864 编码帧、288 解码帧通过，峰值栈 24,236 字节；32 KiB 留约 8 KiB 余量。
但 APP 内的碎片化分配仍失败，Wi-Fi/TLS/PCM 并行预算尚未通过，不能冻结发行。
旧板已证明 8 KiB 不够，会触发栈保护，不能沿用。详见 `tests/opus_target/README.md`。
栈分配失败直接返回 NO_MEM，方向切换会先完整释放上一方向；
`owned_bytes` 仅计上述服务内存，**不包含编码库内部内存**，完整峰值须看真实 heap。
与 MP3、旧本地音效、PCM 共存策略未改动；半双工 APP 必须 stop 后再切换方向。

配置版本 1 的上述行为不变。版本 2 可选一或两项队列，槽位按本次帧格式分配；
`read` 缓冲至少为编码 32+1275 字节、解码 32+本帧 PCM 字节数，返回前缀语义不变。
`LOW_DELAY` 仅用于编码，选择标准 Opus CELT-only 宽带包及 24 KiB 工作栈。
使用固定版本编解码库的 opaque CELT 核心，状态约 5.1 KiB；不包含闲置的 SILK 编码状态。
独立 C3 探针 864 帧编码及标准 Opus 解码互通通过，编码栈峰值 17,568 字节，
60 ms 最大编码耗时 12,189 微秒；这不替代麦克风、TLS 和扬声器并行实测。
版本 2 解码仍支持完整标准 Opus（含 SILK/CELT），先按库返回的大小预留 opaque 状态，
再申请 12 KiB 工作栈和有界队列；初始化和解码仍在受保护的工作线程内执行。
这一顺序避免栈分配先切碎唯一可用的大块；任一步失败都释放本轮已申请资源。
旧版本 1 的 20 KiB 解码栈和原厂封装不变。独立旧路径测得解码栈峰值 8,076 字节，
新 decoder adapter 的实机互通和栈使用须在验收记录中另行确认。
版本 2 的 `PREPARE_CORE` 可预先初始化编解码器，随后释放启动工作栈，保留状态；
首次 submit 按需恢复工作线程。恢复内存不足返回 NO_MEMORY，不消费输入帧，调用者
可以重试或 stop。status 调用也会回收已结束的启动线程；owned_bytes 不含库内部状态。
这是一项通用的显式资源生命周期能力，不依赖 APP ID，旧应用没有被改用此模式。

## 小智测试 APP

`apps/xiaozhi-voice` 使用这些公开接口完成配置/激活、固定私有身份、WS hello、
按住实时录音、20 ms Opus 上行、服务器 TTS 下行、背压、重试与退出。下行 24 kHz Opus
解码到 16 kHz 再交给既有 PCM 播放，无须改变旧 PCM 接口。常用中文字库按字读 Flash。

源码核对依据：[小智文档](https://xiaozhi.dev/docs/)、
[固定版本 WS 实现](https://github.com/78/xiaozhi-esp32/blob/a78ca19d5bc9a12ee0853b9f509530276d36aa03/main/protocols/websocket_protocol.cc)、
[固定版本激活配置](https://github.com/78/xiaozhi-esp32/blob/a78ca19d5bc9a12ee0853b9f509530276d36aa03/main/ota.cc)。
官方接受 XApp 身份、实际语音互通与本地协议回声是不同验收项。
不保存整段录音文件。短时采集缺口最多补 4 个 20 ms 静音帧并记录缺帧数；
更长缺口明确失败并清理资源，避免无限积压或把失真的录音当作成功发送。

## 已有证据与交付门槛

- HTTP：100 生命周期、56 正文边界场景、7 类失败、OOM、取消、请求头注入和凭据释放。
  新增 30 次显式空闲释放/重新请求、忙时拒绝；真实 WAMR、Python 和浏览器校验器均验证
  `http_release` 的 API/权限限制，模拟器离线验证 busy 与 phase 复位。旧 API 2.9 回归通过。
- WS：真实主机 UDP/三个 WS 回环；WSS 故障适配器的证书错误、超时、半写和取消。
  故障适配器不是 TLS 密码学或真实证书验证的证明。
- Opus：主机替身 120 次方向/帧长循环、3840 帧、100 次立即停止、OOM/坏帧恢复；不是原生音质/实时性证明。
- 实际 WAMR：8 个指针越界 trap、20 次非对齐参数生命周期、版本和权限拒绝。
- APP：40 轮真实状态机，传输/编解码替身；提前松键、队列忙、OOM 重试、分片断线重连、
  32 位计时回绕、退出清理。冷 TLS 阶段只释放本 APP 的呈现缓存；旧 APP 路径不变。
- 新老板固件均构建与布局审计通过。后续必须完成四板 TLS、实际 Opus 耗时、音频往返、
  theme/market/旧 APP 回归，再冻结 SDK、API 清单、校验器和模拟器，不能提前标记通过。
